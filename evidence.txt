FINDINGS
================================================================================

--------------------------------------------------------------------------------
FINDING 1 — HIGH — Autoplay soft-lock at "Put the fire out" (real game bug)
--------------------------------------------------------------------------------
Severity:    HIGH for automated/agent play and headless QA; human play unaffected.
Location:    src/story/camp.js:153
Evidence:    Autoplay froze for ~90 s real time at chapter 3 with:
               objective = "Aag ko paani se bujhao (E) · Put the fire out"
               level = camp, player = (0,54), G.interacts.length = 1,
               G.untils = 0, G.timers = 0, no errors.
               The interaction was at (0,60) with r=3.4 — out of reach, and
               nothing in autoplay ever walked to it or resolved it.
Root cause:  camp.js:153 calls G.interact(...) DIRECTLY:
                 await G.interact(new THREE.Vector3(FP.x,0.6,FP.z),
                   'Aag ko stream ke paani se bujhao', { r:3.4, cone:-1 })
             G.interact() (src/game.js:217-222) only registers the interaction
             and returns a Promise — it has NO autoplay branch. The auto
             resolution lives in the use() helper (src/story/helpers.js:98-104),
             which teleports the player to the target and resolves interacts
             when G.auto is true. Every other story interaction uses use()/
             go()/either(); this is the ONLY direct G.interact() call in the
             story scripts.
Impact:      `?auto=1` / `?ch=N&auto=1` headless smoke runs hang forever at this
             step. AI-agent playthroughs cannot pass chapter 3 without manual
             intervention. Human players must walk to the fire and press E, so
             normal gameplay is fine.
Fix:         Replace the direct call with the auto-aware helper:
                 import { use } from './helpers.js'
                 await use(new THREE.Vector3(FP.x,0.6,FP.z),
                   'Aag ko stream ke paani se bujhao', { r:3.4, cone:-1 })
             Also harden G.interact() itself (src/game.js:217) so autoplay can
             never stall on any future direct call: when G.auto, immediately
             resolve and optionally move the player into range.
Related:     src/story/helpers.js:40 `useAt()` is another thin G.interact()
             wrapper with no auto handling. It is currently unused, but it is
             a latent version of the same trap.

--------------------------------------------------------------------------------
FINDING 2 — MEDIUM — Harness "fps-reasonable" check is fake (dev tool bug)
--------------------------------------------------------------------------------
Location:    src/dev/harness.js checks(), fps line
Evidence:    State showed lastDt = 0.05 (≈20 fps under SwiftShader) while
             checks() reported "fps-reasonable: ok, detail: fps 60".
Root cause:  G._fps is only updated inside `if (G._dbg)` in game.js:315, i.e.
             only when the F3 overlay is open. Harness used `G._fps || 60`,
             so with F3 closed it always reported the fallback 60.
Impact:      The bug-detection tool can never detect a frame-rate collapse —
             exactly the class of issue it is supposed to catch.
Fix:         Track fps in the harness's own 500 ms interval from frame deltas
             (e.g. increment a counter each rAF and compute fps), or enable a
             lightweight frame counter in G regardless of _dbg.

--------------------------------------------------------------------------------
FINDING 3 — LOW — Harness dom() reports stale hidden text (dev tool bug)
--------------------------------------------------------------------------------
Location:    src/dev/harness.js dom()
Evidence:    dom().objective returned the previous chapter's objective
             ("...Knock on a door for help ▸ 49 m") while level was "escort" and
             ui.objText was null / G.goal was null. The HUD had correctly hidden
             the element (nav.js removes the 'show' class) but left textContent.
Root cause:  dom() reads element.textContent unconditionally, without checking
             whether the element is visible.
Impact:      Agent observations can be misled by stale UI text from earlier
             chapters. Cosmetic/dev-only.
Fix:         In dom(), return text only if the element has class 'show' and is
             not inside a hidden ancestor; otherwise null.

--------------------------------------------------------------------------------
FINDING 4 — LOW — Harness "not-stuck" check false-positives on stationary scenes
--------------------------------------------------------------------------------
Location:    src/dev/harness.js periodic sampler / checks()
Evidence:    checks() reported "not-stuck: ok=false, no progress for 143s"
             while the player was legitimately standing through a long dialogue
             and the story was advancing normally (subtitles changing, levels
             changing).
Root cause:  The check only measures player displacement over 45 s; it does not
             account for dialogue/cinematic scenes where standing still is the
             intended state.
Impact:      False alarms that dilute real bug signal.
Fix:         Reset the stillness timer whenever G.interacts, G.timers, G.untils,
             subtitles, level, or goal change; only flag stuck when the story
             itself is also idle for the full window.

--------------------------------------------------------------------------------
FINDING 5 — INFO — Opening cinematic is very slow under software WebGL
--------------------------------------------------------------------------------
Evidence:    After "New Game", the two opening G.shot() camera moves (4.2 s +
             3.4 s) plus title card took roughly 2-3 minutes of real time before
             the first objective/dialogue appeared. G.lastDt was pinned at 0.05.
Cause:       The main loop clamps dt to 0.05 s per frame (game.js:277); with
             SwiftShader running at very low fps, 7.6 s of cinematic time needs
             ~152 rendered frames. On a real GPU this is ~8 s as designed.
Impact:      Environment-only; not a gameplay bug. Automated tests should use
             ?fast=6+ (fastSim) or skip the intro with Space/Enter.
Note:        G.shot() allows Space/Enter to skip after 0.8 s (game.js:256).
